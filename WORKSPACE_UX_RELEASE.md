# TPA workspace UX release

This release adapts the requested profile-dropdown, action-search and bento patterns to the existing React/CSS architecture. It preserves the current brand, routes, permissions, saved answers, evidence, publication snapshots and verification decision service.

## Shared foundation

- Compact account controls replace the staff sidebar footer and are reused in signed-in public and member headers. Profile, security, workspace/public navigation and sign-out remain available. Notifications stay accessible on mobile.
- Light, Dark and System are browser preferences, independent of theme identity. System is the default. A head bootstrap applies the resolved mode before body rendering, listens for OS changes and synchronises storage changes across tabs. Themes is disabled and labelled Coming later.
- Semantic surface, text, border, input and status tokens support both modes. Uploaded images are not filtered or inverted. Document, flyer and QR preview canvases retain light colours, as does print output.
- Search is read-only, authenticated and permission-filtered, with parameterised PostgreSQL queries, escaped literal wildcards, bounded per-source results, driver timeouts, a 30-result balanced cap and additive indexes. Private file bytes, authentication credentials, action tokens and encrypted delivery payloads are excluded.
- Search destinations include record selection links. Plain anchors preserve existing document-level unsaved-change interception. The command dialog supports Ctrl/Cmd+K, arrows, Tab, Escape and native modal focus containment.
- Attention uses current workflow conditions, fixed categories and priorities. Reading a panel does not acknowledge, resolve or alter a workflow. Bulk search remains owner-scoped; report presets retain dataset permissions and private/shared ownership rules.

## Validation and evidence

Validation is in progress. Local unit tests and a production build passed. The isolated database/auth/worker suite passed seven tests; onboarding and new search/attention HTTP suites passed. The first local browser run was invalidated by replacing its build while its server was running; that run is not release evidence. It was stopped and its owned test database removed. A fixed-build browser run and CI must pass before deployment.

Browser coverage includes desktop (including 1123×930), tablet and phone, anonymous mode controls, reload and cross-tab synchronisation, OS changes, keyboard dismissal/focus, command search, record links, all permitted administrator destinations, overflow, requirements grouping, action-specific reasons and badge preservation after corrections. Existing onboarding journeys retain autosave, refresh/recovery, conflicts and failed upload coverage. Tests use isolated databases and a mail sink.

Before screenshots are in `.local/workspace-ux/`; after screenshots, traces and CI reports are generated as test artifacts. These local artifacts are not committed and contain only the intended page captures.

## Deployment and rollback

Deploy only an exact checked commit after lint, typecheck, unit/database/HTTP/browser checks and build pass. Migrations 021 and 022 are additive indexes; migration checksums remain enforced. No external search service, new worker/service, campaign or automatic verification decision is introduced.

Rollback to the prior runtime commit `7d8d968c3b1d5f2036f5efaf119b7c39b4f65c82` restores the previous presentation. Leave additive indexes in place; do not drop saved data, identities, policy versions, submissions or publication snapshots. Restoring Fax remains a separate requirements publication using the same identifier.
